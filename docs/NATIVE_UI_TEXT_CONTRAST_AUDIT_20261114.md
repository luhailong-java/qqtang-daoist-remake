# 原生界面文字与底色核对

选区地区名称显式使用浅米白，适配深色底。`uiSelSect` 中 `sect1.children.name` 继承 `TLabel, Static`，并通过符号赋值设置 `drawcolor=zoneChooseColor`、`textEdgeColor=maskColor`。`uiMain` 根作用域的字面量分别将二者定义为 `[255,250,236,255]` 和 `[51,51,51,255]`。父代码的基类读取、构造和保存分别位于字节偏移 9、12、15、27、28。

`sect1.framescheme` 为 `[[-1,-1,0,0,-1,-1,-1,-1]]`，部分状态省略行图，文字直接画在屏幕底图上。因此屏幕地区列表与可选行图都需要适配浅米白文字。以 `[37,77,66]` 深玉底和 `[243,234,210]` 浅纸底作为示例，前景与背景的计算对比分别记录在 JSON。

此前根据邻接字面量中缺少 `drawcolor`，推断它使用 `TLabel` 默认黑字，这个判断已撤回。该识别方式遗漏了 `LOAD_NAME` 全局符号赋值。审计现同时记录类构造、属性的符号赋值和 `uiMain` 全局字面量，不能把字面量识别器未提取到的属性视作不存在。

密码框保持深色输入底。其输入控件继承 `TEditPassword`，模板显式使用白字。地图筛选的条目名称及当前选项名称也显式指定白字，深色底适配这两类字段。普通 `TEdit` 与 `TLabel` 的黑字默认值单独记录。

系统消息框正文也显式设置 `drawcolor=zoneChooseColor`，实际使用浅米白。该子类为裸类定义并设置 `type='LABEL'`，不能因它显示为 LABEL 就直接套用 `TLabel` 模板默认。正文区域需要深底，蓝色超链接则需要独立解决对比。原超链接颜色由两个复用整数常量构造，无法在保持 `co_code` 不变时单独替换为任意金色四元组。 [超链接颜色数据补丁计划](native-sysmsgbox-color-patch-plan-20261114.json)

主窗口选定将复用整数常量 6 从 0 改为 200，令超链接前景变为 `[200,200,255,255]`、边缘变为 `[255,200,200,200]`。本审计只在内存修改其四字节整数数据并重新解析，确认所有代码作用域的 `co_code`、URL、回调、控件几何与非颜色字面量保持原字节或原值，只有两项颜色属性变化。精确替换范围、改后 SHA-256 和全部作用域代码哈希见补丁计划，未写出修改后的 PYC 文件。

对局地图名使用的 `lightColor` 在 `uiMain` 定义为白色。大厅玩家名称由 `updatePlayer` 使用 `normalNameColor=[199,242,252,255]` 或 `memberNameColor=[255,189,222,255]` 设置，也适配深色底。

逐模块源 SHA-256、类构造字节、属性符号赋值、模板及全局颜色和地区行映射见 [只读核对 JSON](native-ui-text-contrast-audit-20261114.json)。本记录保存静态证据，原客户端运行中的文字与状态仍待检查。
