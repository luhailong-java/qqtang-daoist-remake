# 世界头饰帧与挂点合同

这份合同管真正world sprite候选，不使用256×256背包图的边距、中心或尺寸。当前未接运行，geometryAccepted、visualAccepted、runtimeAdopted均为false。

## 尺寸与注册

exportDensity=4只表示每个legacy源像素导出4个图像像素。新PNG必须仍按源帧的逻辑宽高绘制。不能把132×88当132×88逻辑单位，也不能把背包224px可见区当世界尺寸。

每帧从新画母图裁出，经一次等比缩放，放入该帧原alpha包围框×4；X居中、Y底对齐，具体scale/placement/原始矩形逐帧记录。没有非等比拉伸。原rawOffset没有被自动居中归零。固定画布相符不等于内部轮廓与跨帧一致性已通过。

可计算但不冒充原生挂点的公共包围框：

- 42 raw总体边界[28,4,68,30]，尺寸40×26。相对该框左上角的帧位置依次[0,0]、[4,0]。
- 54 raw总体边界[33,-2,66,24]，尺寸33×26。相对该框左上角的帧位置依次[0,4]、[0,0]、[0,3]、[0,4]。

这些是`offset+size`的代数包围框，不是已确认的角色头节点。54的源declaredCanvas为33×26，不能将每个33×22帧拉伸到33×26；额外高度来自帧间位移。

## 头部挂点接口与待证部分

接入方应提供同一legacy头饰层原点及legacy像素到游戏逻辑单位的转换。不得为每个item单独按背包中心或帧底重新定义挂点，这会消除源位置差异与起伏。rawOffset坐标系的原点、正负号及其与当前角色头部骨点/节点的关系尚未由原生运行或本项目实机对照确认，不能猜一个[50,30]之类常量当结论。

在未来**验证采用加偏移约定后**，候选绘制方式是：将PNG按logicalFrameSize绘制，左上角为headLayerOrigin加frameOffsetRaw。另一等价组织方式是先按公共包围框内的相对位置合成，再加公共框原点；二者不能重复加偏移。当前不批准任一方式自动运行。

`frameOffsetPxAtDensity4`只供图像尺度核对，不可与逻辑rawOffset同时使用造成四倍位移。sourceHeaderUnknownWordsAt24And28原样保留，没有将其猜成额外挂点。

后续必须核对当前人物头部落点、坐标符号/单位、相同朝向和缩放下的相对位置、每帧主体/高光连续性、alpha散点与裁边，并取得播放时序证据或明确的新项目时序决定。未完成这些检查前，完整动画验收与runtimeAdopted继续为false。当前覆盖数量见README与world-art.json；本节最初42/54的6个候选仅为早期批次记录。
