# 原生 UI 图像格式补齐

本轮补齐剩余 UI 遇到的格式，未启动原客户端或执行其代码。编码入口是 `scripts/native-ui-format.py`，安装器与回读器使用同一严格检查；画面、时序和运行验收仍待完成。

| 源格式 | 保留内容 | 自有图像的编码方式 |
|---|---|---|
| DIMG（含 `.gsa` 后缀） | 画布、方向、帧数、空位、偏移、像素模式与全部非像素字节 | 原 RGB565／33 阶 Alpha、BGRA 或不透明 BGR 像素平面 |
| 未压缩 TGA 24／32 位 | 18 字节头、26 字节标准尾、尺寸、深度、四种原点方向 | 原 BGR／BGRA 存储方向；24 位必须不透明 |
| 单帧、不透明 GIF89a | 原画布、整幅图像描述框、500ms、loop0、disposal1、background 索引0、无交错 | 原创全幅画稿重新量化调色板和 LZW；长度和调色板允许改变 |

两个 GIF 为 140×226 的默认人物资料插图。新稿不含旧人物；原男女选择绑定保留。GIF 的 `pixelMode=16` 是工具内部“不透明解码图”的分类，不是 GIF 文件上的原生像素模式字段。真实格式、P 模式调色板与 GIF 属性另行记录。GIF 不适用 DIMG 的固定长度／非像素逐字节规则，安装器改为逐项验证其结构与时间属性。

`fight.gsa` 经魔数、九帧边界、像素平面和 EOF 完整检查，确证为 DIMG；与包内 `arror.img` 26239 字节完全相同，两者使用同一套自有箭头。历史 census 的 opaque 记录不改写，另以 [格式补证](../references/qqtang-ui-data/native-ui-format-refinements-20261114.json) 追加 1 个图像路径、9 个位置，最新覆盖审计应用此补证。

既有 DIMG 编码算法的 AST 不变；713 份地图、头饰和库存图像重新编码后字节一致，见 [兼容性证据](native-codec-tga-extension-20261114.json)。3941 库存图标仍保留另记的版本／不透明尾部兼容例外，未因新增格式扩大例外范围。

19 项本地格式与安装回归检查覆盖三种 DIMG 像素平面、空位、24／32 位 TGA 四方向、GIF 计时与处置、动画／透明／截断拒绝，以及修改图片哈希后仍不能绕过 TGA 头或 GIF 计时保护。GIF 只接收结构正确的 GCE 和 NETSCAPE2.0 扩展；comment、plaintext、自定义应用、非零像素宽高比、用户输入等待与未知保留位组合均拒绝，避免换图时静默丢失未知语义。

两份真实源的 GCE 控制字节均为 `0xC4`，含旧高保留位 `0xC0`。这些位作为已知兼容形态保留，写入自有 GIF 实际解析到的控制位置，安装器要求与源一致，未清成 `0x04`。GCE 位偏移和高保留位在元数据中单列，不混入五项标准 GIF 属性。真实 ZIP 的两文件 SHA 与回放已纳入本地回归；无私有 ZIP 的 CI 对该一项跳过，独立合成的同类兼容／篡改回归继续执行。
